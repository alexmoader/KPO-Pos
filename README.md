# Зависимости проектов и DDD

Стрелка идет от проекта, который использует другой проект, к его зависимости.

```text
Pos.Presentation   → Pos.UseCases → Pos.Models
Pos.Infrastructure → Pos.UseCases
Pos.Host           → Pos.Presentation, Pos.UseCases, Pos.Infrastructure
Pos.Tests          → Pos.Models, Pos.UseCases, Pos.Infrastructure
```

`Pos.Host` собирает зависимости через DI в [Program.cs](Pos.Host/Program.cs). Интерфейсы репозиториев лежат в [Pos.UseCases/Ports](Pos.UseCases/Ports), а их JSON-реализации в `Pos.Infrastructure`. Сценарии работают через эти интерфейсы, а `Pos.Models` содержит правила оценивания и не зависит от других проектов.

**Как DDD реализован в проекте**

- **Единый язык.** Студент, рубрикатор, критерий, оценка и итог используются в описании задачи и в именах моделей (`Student`, `Rubric`, `Criterion`, `Evaluation`, `FinalResult`).
- **Сущности и агрегаты.** `Student` и `Rubric` имеют свои ID и являются корнями агрегатов. Студент управляет своими оценками через `SetEvaluation` и `RemoveEvaluation`. `Criterion` — сущность со своим ID внутри рубрикатора, а `Rubric.AddCriterion` проверяет уникальность этого ID.
- **Оценка как объект-значение по смыслу модели.** `Evaluation` хранит ID критерия и балл. У оценки нет отдельного ID, она неизменяемая и при исправлении заменяется целиком внутри студента.
- **Инварианты.** При выставлении оценки модель через `EvaluationFactory` проверяет наличие критерия в рубрикаторе и допустимость балла. Студент хранит одну текущую оценку на критерий. Остальные правила перечислены ниже.
- **Доменный сервис.** `WeightedResultCalculator` рассчитывает итог по текущим оценкам студента и весам критериев из рубрикатора. Расчет использует данные двух агрегатов.
- **Репозитории.** `IStudentRepository` и `IRubricRepository` загружают и сохраняют агрегаты. Их реализации преобразуют модели в DTO для записи в JSON и восстанавливают модели при чтении.

# Инварианты и соглашения:

**ВЕС**
- Вес критерия - положительное целое число, которое задает его относительный вклад в итог. Веса могут иметь любую положительную сумму. Например, веса 1 и 3 дают те же доли, что 25 и 75.
- Для каждого критерия делим набранный балл на максимальный и умножаем полученную долю на вес. Складываем вклады, делим на сумму весов всех критериев и умножаем на 100:
$$
\text{Итог} = 100 \times \frac{\sum \left( \frac{\text{балл}}{\text{максимум}} \times \text{вес} \right)}{\sum \text{вес}}
$$
- Пропущенная оценка дает нулевой вклад, при этом вес критерия входит в сумму весов. При пустом рубрикаторе итог рассчитать невозможно. Итог вычисляется из текущих оценок и рубрикатора.

**РУБРИКАТОР**
- Рубрикатор один на программу. Однако у него оставлены ID и Имя для возможного расширения, что их может быть несколько. Для интерфейся репозитория рубрикатора я написал Get без аргументов исходя из того, что рубрикатор один. 

---

**ИНВАРИАНТЫ**
- Идентификаторы студента, рубрикатора и критерия не могут быть Guid.Empty. Имя студента и названия рубрикатора и критерия не могут быть пустыми или состоять только из пробелов.

- Максимальный балл и вес каждого критерия строго больше нуля. Идентификаторы критериев внутри одного рубрикатора уникальны.

- Оценку можно выставить только по критерию из действующего рубрикатора. Допустимый балл лежит в диапазоне от 0 до максимума критерия включительно.

- У студента может быть только одна текущая оценка по каждому критерию. Допустимое исправление заменяет старый балл, а отклоненное исправление сохраняет прежнюю оценку.

# Тестирование
По мере разработки приложения я писал тестирование для проверки работы классов, методов и логики работы приложения

- **StudentEvaluationTests.cs** - Тесты, покрывающие Student.SetEvaluation(). Мы не можем записывать некоректные баллы, не можем добавлять критерии по одному ID, не можем вписать оценку по критерию, которого нет в рубрикаторе
- **WeightedResultCalculatorTests.cs** - Тесты для проверки работы формулы вычисления итоговой оценки. 
- **SetEvaluationHandlerTests.cs** - Тесты для проверки работы обработчика выставления оценки. Используется самописный репозиторий, чтобы проверить, когда вызывается сохранение студента.
- **RemoveEvaluationHandlerTests.cs** - Тест на отмену оценки. Первый вызов удаляет оценку и сохраняет студента, а повторный возвращает false. После отмены критерий дает нулевой вклад в итог.
- **RoundedResultCalculatorTests.cs** - Тест для проверки округления итоговой оценки до двух знаков после запятой.
- **ExportResultsHandlerTests.cs** - Тесты для проверки выбора стратегии экспорта. Итог и путь к файлу передаются только выбранной стратегии CSV или JSON.
- **JsonRepositoryTests.cs** - Интеграционный тест для проверки хранения в JSON. После повторного чтения файла восстанавливаются студент, рубрикатор и оценки, а итог остается тем же.

# Сборка

На каждый слой приложения был создан свой .csproj файл, позволяющий явно указать завимости слоев. (что допустим домен не зависит ни от чего, usecases от домена и тд.)

Для сборки нужен .NET SDK 10. Все команды ниже я запускаю из папки `Pos`, где лежит `Pos.slnx`.

```bash
dotnet build Pos.slnx
dotnet test Pos.slnx
```

Приложение запускается через проект `Pos.Host`. Если запустить программу без параметров, откроется консольное меню, а данные будут сохраняться в `pos-data.json` в текущей папке.

```bash
dotnet run --project Pos.Host/Pos.Host.csproj
```

Параметры программы указываются после `--`.

- `menu demo.json` - открыть меню и использовать `demo.json` для хранения данных. Если файла еще нет, он появится при первом сохранении.
- `init demo.json` - заполнить новый файл демонстрационными данными. Программа добавит студента, два критерия и оценки, затем выведет ID студента и итог 57,5%. Для этой команды нужно указать файл, которого еще нет.
- `show demo.json <ID студента>` - загрузить данные из файла и вывести итог выбранного студента. Вместо `<ID студента>` нужно подставить GUID, который вывела команда `init` или который можно посмотреть в списке студентов в меню.

Например, для демонстрации я сначала создаю данные, а потом открываю этот же файл через меню:

```bash
dotnet run --project Pos.Host/Pos.Host.csproj -- init demo.json
dotnet run --project Pos.Host/Pos.Host.csproj -- menu demo.json
```

В меню через пункт 2 можно посмотреть ID студента, через пункт 8 вывести итог, а через пункт 9 выгрузить его. Для выгрузки нужно ввести ID студента, формат `csv` или `json` и путь к новому файлу.
